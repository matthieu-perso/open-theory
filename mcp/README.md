# OpenTheory Core MCP Server

> Model Context Protocol (MCP) server enabling autonomous AI agents to formalize, verify, and submit mathematical proofs in Lean 4 with Mathlib.

## 1. Why the MCP Lives in `open-theory-core`

The OpenTheory ecosystem is partitioned into two distinct repositories:

1. **`open-theory-core` (This Repository)**: The formal math library containing the Lean 4 environment, `lakefile.lean`, Mathlib, `scripts/audit_axioms.lean`, and LaTeX blueprints. The autonomous agent needs direct local access to the Lean compiler and Lake build system.
2. **`open-theory-platform`**: The Next.js web application and interactive DAG visualizer. It displays proof state and bounties by consuming the `blueprint.json` generated by this repository's CI.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        AUTONOMOUS AGENT LOOP                           │
│                                                                        │
│   1. get_open_bounties     ──▶ Scans blueprint.json for bounties       │
│   2. get_lemma_context     ──▶ Fetches LaTeX intuition & predecessors  │
│   3. verify_lean_proof     ──▶ Invokes Lake & scripts/audit_axioms.lean│
│   4. commit_proof          ──▶ Replaces sorry, tags \leanok & commits  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ git push / PR
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                    CI (open-theory-core GitHub Actions)                │
│   - Executes: lake build                                               │
│   - Executes: lake env lean --run scripts/audit_axioms.lean            │
│   - Generates: blueprint/blueprint.json                                │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Webhook / API
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│               WEB PLATFORM (open-theory-platform Next.js)               │
│   - Reads latest blueprint.json                                        │
│   - Turns DAG node from Blue/Red to Green 🟢                           │
│   - Disburses escrowed bounty to solver                                │
└────────────────────────────────────────────────────────────────────────┘
```

    ├── package.json             # @modelcontextprotocol/sdk & zod
    ├── tsconfig.json
    ├── dist/                    # Compiled JavaScript executable
    └── src/
        ├── index.ts             # Stdio MCP server entrypoint

            ├── lean.ts          # verify_lean_proof (Lake & audit runner)

## 3. The 4 Exposed Tools

### `get_open_bounties`
Discovers actionable theorem bounties from `blueprint/blueprint.json`.

- **Inputs**:
  - `min_bounty` *(number, optional)*: Filter by minimum USD reward (e.g. `2000`).
  - `max_bounty` *(number, optional)*: Filter by maximum USD reward.
  - `kind` *(string, optional)*: `'lemma' | 'theorem' | 'conjecture' | 'all'`.
  - `status` *(string, optional)*: `'sorry' | 'unproven' | 'all'`.
  - `only_ready_to_prove` *(boolean, optional)*: If `true`, returns only lemmas whose dependencies are already 100% verified.
- **Output**:
  - Array of open targets containing `id`, `code_id`, `bounty_usd`, `status`, `lean_file`, `dependencies_ready`, and `unverified_dependencies`.

---

### `get_lemma_context`
Extracts comprehensive mathematical context for an agent to formulate a proof.

- **Inputs**:
  - `lemma_id` *(string, required)*: Label or name (e.g. `'lem:spectral_bias_mup'` or `'spectral_bias_mup_alignment'`).
- **Output**:
  - `latex_statement`: The formal human mathematical statement.
  - `informal_proof_sketch`: Literature proof ideas or bounty notes.
  - `lean_target`: Current `.lean` declaration with line number and `sorry`.
  - `predecessors`: Array of prerequisite lemmas/definitions, including their full Lean code and verification status.
  - `axiom_audit_policy`: Allowed standard axioms (`Classical.choice`, `Quot.sound`, `propext`).

---

### `verify_lean_proof`
Runs the Lean 4 compiler kernel and axiom auditor against proposed tactics.

- **Inputs**:
  - `lemma_id` *(string, optional)*: ID of target lemma.
  - `proof_code` *(string, optional)*: Proposed tactic block or term replacing `sorry`.
  - `file_path` *(string, optional)*: Specific file to check.
  - `run_axiom_audit` *(boolean, optional, default: true)*: Runs `scripts/audit_axioms.lean`.
  - `dry_run` *(boolean, optional, default: true)*: Reverts source files after testing.
- **Output**:
  - `success` *(boolean)*: True if proof builds cleanly with 0 errors, 0 `sorry`, and 0 illegal axioms.
  - `has_sorry` *(boolean)*.
  - `unauthorized_axioms` *(string[])*.
  - `unsolved_goals` *(string[])*.
  - `messages`: Structured line/column diagnostics with severity.

---

### `commit_proof`
Permanently inserts verified tactics into the math library, updates the LaTeX blueprint, and commits to Git.

- **Inputs**:
  - `lemma_id` *(string, required)*: Lemma to prove.
  - `proof_code` *(string, required)*: Verified tactics replacing `sorry`.
  - `branch_name` *(string, optional)*: Git branch (defaults to `proof/<lemma_id>`).
  - `commit_message` *(string, optional)*: Custom commit message.
  - `verify_before_commit` *(boolean, optional, default: true)*: Validates proof before committing.
  - `update_blueprint` *(boolean, optional, default: true)*: Adds `\leanok` to `blueprint/src/content.tex` and runs `export_blueprint.py`.
- **Output**:
  - `commit_hash`, `branch`, `files_modified`, `diff_stat`, `blueprint_updated`.

## 4. Setup & Installation

### Build Server
```bash
cd mcp
npm install
npm run build
```

### Running Locally
```bash
node dist/index.js
```

## 5. Client Configuration

### Cursor (`.cursor/mcp.json` or Global MCP Settings)
```json
{
  "mcpServers": {
    "open-theory-core": {
      "command": "node",
      "args": ["/Users/matthieu/open_theory/mcp/dist/index.js"],
      "env": {
        "OPEN_THEORY_ROOT": "/Users/matthieu/open_theory"
      }
    }
  }
}
```

### Claude Desktop (`claude_desktop_config.json`)
```json
{
  "mcpServers": {
    "open-theory-core": {
      "command": "node",
      "args": ["/path/to/open-theory-core/mcp/dist/index.js"]
    }
  }
}
```

## 6. Environment Variables

| Variable | Description | Default |
| :--- | :--- | :--- |
| `OPEN_THEORY_ROOT` | Absolute path to repository root | Discovered dynamically from current working directory |
| `LAKE_PATH` | Path to `lake` executable | Discovered from `PATH`, `~/.elan/bin/lake`, or `/opt/homebrew/bin/lake` |
| `LEAN_PATH` | Path to `lean` executable | Discovered from `PATH` or `~/.elan/bin/lean` |
